# ADR-011: UUIDv7 primary keys

**Status:** Accepted

Entity ids (starting with `user.id`) are version 7 UUIDs generated by the application (`UuidV7` in `libs/api`), stored in native MariaDB `UUID` columns and exposed in resource names as lowercase canonical strings (`users/{uuidv7}`).

Reasons: ids appear in public resource names, so they must not be enumerable; they can be created without a database round trip (outbox events, offline clients, future service extraction); and being time-ordered they append to the primary key index and work as keyset pagination keys. Verified against MariaDB 11.4: `ORDER BY id` returns v7 ids in creation order.

Consequences: 16 byte keys instead of 8; ids are not human-friendly; the creation time is derivable from an id. High-volume child resources such as messages may later use a 64-bit snowflake id via a separate ADR.
